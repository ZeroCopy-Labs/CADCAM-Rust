## 环境与构建

准备 Cargo、PowerShell 7 和 Windows GNU 链接环境。项目通过 `rust-toolchain.toml` 指定工具链，可先检查：

```powershell
rustup show active-toolchain
cargo --version
pwsh --version
```

在仓库根目录执行：

```powershell
.\build.ps1
.\run.ps1 "D:\CAD\sample.dxf"
```

`build.ps1` 将工作目录切到脚本目录，设置指定的 `RUSTUP_TOOLCHAIN`，执行 `cargo build -p cad-app`，失败报错；成功产物为 `build/cargo/debug/cad-app.exe`。`run.ps1` 总是先构建，再启动程序并透传参数。

已构建时可直接启动：

```powershell
.\build\cargo\debug\cad-app.exe "D:\CAD\sample.dxf"
```

直接启动不构建，需确认产物与源码一致。快速 NC 导出依赖进程工作目录，配置及最近文件位置见[使用指南](使用指南.md)。

### 人工验收

按“输入 → 处理 → 最终结果”记录具体图纸、单位、配置和预期结果：

1. **导入与显示**：核对固定 DXF/DWG 的实体/单元数、图层颜色、三维坐标、单位、警告及不支持实体。
2. **交互与规划**：核对相机、空间选择映射、正反框选、界面输入阻隔、截面/断面、区位、组末断面、排序及起点箭头。
3. **状态变化**：编辑配置并重算，改变 CAM、手动重排及换图纸，核对计划、轨迹统计与文本是否对应同一状态。
4. **实际文件**：分别普通/快速导出，检查 NC 的单元覆盖、顺序、单位、规则代码、圆弧/折线、A 连续性、过切及首尾移动。
5. **证据范围**：单独记录 GUI、性能和控制器/实机验证是否执行；未执行项标为未验证。

`build/`、`temp/` 中旧样本、截图、日志和 NC 是未跟踪资料，不是所有检出都有的固定测试集。需共同复现时，在具体任务中明确样本来源、配置和验收标准。

## 修改入口与边界

| 行为 | 优先追踪 |
|---|---|
| 格式、诊断、OCS/WCS、几何转换 | cad-core 的 import、convert、model |
| 显示曲线、颜色、包围盒、属性 | `display.rs` |
| 端点连接与单元闭合 | `cam.rs` |
| 截面、断面、区位、分组、排序、方向和起点 | `cam_analysis.rs` |
| 四轴姿态、连续角度、抬刀、过切、圆弧识别 | `cam_trajectory.rs` |
| 配置/默认值、校验、模板、格式化 | `gcode.rs` |
| 操作触发、状态、选择、预览和两个导出入口 | `main.rs` |

从实际触发入口追到最终显示或输出，避免只检查局部函数。保持 cad-core 独立，只改任务所需范围，不顺带清理无关代码。
